Root cause patterns

Port routing text: "Freight collect at destination port" caused Gemini to pick up the wrong port for port_of_discharge on TD-02.
HS label variants: Hungarian customs labels VTSZ and SZJ on TD-06 not mapped to standard HS field — 6-digit "290722" returned instead of 8-digit "29072200".
Letterhead extraction: Multi-invoice packing lists (TD-04, TD-08) with shipper/consignee printed in header banners — not in labeled boxes — missed consistently.
COO multi-column layout: Field-10 of a Certificate of Origin references the underlying invoice number — Gemini did not infer this cross-reference.
Document type confusion: TD-05 AWB execution date returned as invoice_date — prompt did not explicitly prohibit non-invoice dates for AWBs.

Benchmark Design

Why this benchmark exists

Indian trade document extraction is a real production problem for Customs House Agents (CHAs) filing Bills of Entry and Shipping Bills. Documents arrive as scanned PDFs — often multilingual, with non-standard layouts — and even minor field extraction errors cause customs delays. No public benchmark tests LLM extraction on this specific document corpus.

Controls used

Ground truth frozen before model runs — all 80 expected values were locked before any Gemini query. This prevents anchoring bias (the evaluator seeing model output before deciding what's "correct").
Temperature = 0.0 — fully deterministic. Every run produces the same output for the same document, making the benchmark reproducible.
Single frozen prompt — the exact same prompt was used for all 8 documents. Changing prompts mid-run would make results incomparable across documents.
Safe-abstention scoring — fields genuinely absent from a document type (e.g., total_invoice_value on a packing list) are scored as True Negative when the model correctly returns null. A model that hallucinates values for absent fields is penalized as False Positive.
Wilson 95% CI — reported alongside point estimates throughout, because n=8 documents is a small sample and point estimates alone are misleading.

Security note

All documents used in this benchmark are synthetic or fully redacted samples. No real client, customer, or supplier data was uploaded to any AI service. All proper nouns, addresses, invoice numbers, and bank details were replaced with invented placeholders of the same format before use.

The frozen prompt

Every extraction used this exact prompt at Temperature 0.0:

Frozen extraction prompt (verbatim)
Extract the following 10 fields from this Indian trade document. Return ONLY valid JSON with exactly these keys. If a field is not present in the document, return null for that key. { "shipper_name": "Full legal name of the shipper/exporter as printed", "consignee_name": "Full legal name of the consignee/importer as printed", "invoice_number": "Invoice reference number — only from an invoice, not an AWB or other doc", "invoice_date": "Date on the invoice in YYYY-MM-DD format — only from an invoice", "hs_code": "Harmonized System code (6–8 digits) — use the most specific one found", "port_of_loading": "Port where goods were loaded — use the explicit port label only", "port_of_discharge": "Port where goods will be discharged — use the explicit port label only", "total_invoice_value": "Total invoice amount as a number — null if document is not an invoice", "currency": "3-letter ISO currency code (e.g. USD, INR, EUR)", "country_of_origin": "Country where goods were manufactured or produced" } Rules: 1. Return ONLY the JSON object. No explanations, no markdown. 2. Use null (not "", not "N/A") for missing fields. 3. For port fields: extract only from explicit port labels. Do not infer ports from routing instructions or freight terms. 4. For hs_code: if multiple HS codes appear, return the most specific (longest) one. 5. For invoice_number and invoice_date: these fields are specific to commercial invoices. Return null for AWBs, packing lists, COOs, and other non-invoice documents. 6. For total_invoice_value: return null for packing lists, COOs, and AWBs. 7. If a field label uses a non-English equivalent (e.g., VTSZ, SZJ for HS code in Hungarian docs), still extract the value.
