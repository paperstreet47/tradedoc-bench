Failure Analysis

18 total failures across 80 field extractions.

Share of 18 total failures. Dominant mode: under-extraction (FN), not hallucination (FP).

Root cause patterns

Port routing text: "Freight collect at destination port" caused Gemini to pick up the wrong port for port_of_discharge on TD-02.
HS label variants: Hungarian customs labels VTSZ and SZJ on TD-06 not mapped to standard HS field — 6-digit "290722" returned instead of 8-digit "29072200".
Letterhead extraction: Multi-invoice packing lists (TD-04, TD-08) with shipper/consignee printed in header banners — not in labeled boxes — missed consistently.
COO multi-column layout: Field-10 of a Certificate of Origin references the underlying invoice number — Gemini did not infer this cross-reference.
Document type confusion: TD-05 AWB execution date returned as invoice_date — prompt did not explicitly prohibit non-invoice dates for AWBs.

Benchmark Design

Why this benchmark exists

Indian trade document extraction is a real production problem for Customs House Agents (CHAs) filing Bills of Entry and Shipping Bills. Documents arrive as scanned PDFs — often multilingual, with non-standard layouts — and even minor field extraction errors cause customs delays. No public benchmark tests LLM extraction on this specific document corpus.

Controls used

Ground truth frozen before model runs — all 80 expected values were locked before any Gemini query. This prevents anchoring bias (the evaluator seeing model output before deciding what's "correct").
Temperature = 0.0 — fully deterministic. Every run produces the same output for the same document, making the benchmark reproducible.
Single frozen prompt — the exact same prompt was used for all 8 documents. Changing prompts mid-run would make results incomparable across documents.
Safe-abstention scoring — fields genuinely absent from a document type (e.g., total_invoice_value on a packing list) are scored as True Negative when the model correctly returns null. A model that hallucinates values for absent fields is penalized as False Positive.
Wilson 95% CI — reported alongside point estimates throughout, because n=8 documents is a small sample and point estimates alone are misleading.

Security note

All documents used in this benchmark are synthetic or fully redacted samples. No real client, customer, or supplier data was uploaded to any AI service. All proper nouns, addresses, invoice numbers, and bank details were replaced with invented placeholders of the same format before use.

The frozen prompt

Every extraction used this exact prompt at Temperature 0.0. Note the schema requests evidence (verbatim quote) and page (1-indexed page number) alongside each value — evidence quality was not separately scored in v0.1, only value fields were evaluated against ground truth. Evidence scoring is planned for v0.2.

Frozen extraction prompt (verbatim)
You are extracting structured information from a trade document for an operational review workflow. Return only valid JSON. Do not include Markdown, explanations, or any text before or after the JSON. Use this schema exactly. Every field must appear. { "document_number": { "value": null, "evidence": null, "page": null }, "document_date": { "value": null, "evidence": null, "page": null }, "seller_name": { "value": null, "evidence": null, "page": null }, "buyer_name": { "value": null, "evidence": null, "page": null }, "total_invoice_value": { "value": null, "evidence": null, "page": null }, "currency": { "value": null, "evidence": null, "page": null }, "hs_code": { "value": null, "evidence": null, "page": null }, "country_of_origin": { "value": null, "evidence": null, "page": null }, "port_of_loading": { "value": null, "evidence": null, "page": null }, "port_of_discharge": { "value": null, "evidence": null, "page": null } } Definitions: document_number: the primary identifier of this document. For an invoice, extract the invoice number. For a bill of lading or airway bill, extract the B/L or AWB number. document_date: the primary issue or document date. For an invoice, extract the invoice date. seller_name: an entity explicitly labelled seller, exporter, shipper, consignor, or equivalent. buyer_name: an entity explicitly labelled buyer, consignee, importer, or equivalent. total_invoice_value: a value explicitly labelled invoice total, grand total, final amount, declared value, or total. Do not calculate totals and do not return line-item values or subtotals. currency: the currency explicitly associated with the total invoice value. hs_code: an HS, HSN, tariff, or commodity code only when explicitly printed in the document. country_of_origin: a country only when explicitly labelled as country of origin, origin, or equivalent. port_of_loading: a port only when explicitly labelled port of loading, POL, place of receipt, or equivalent. port_of_discharge: a port only when explicitly labelled port of discharge, POD, destination port, place of delivery, or equivalent. Rules: Extract only information explicitly supported by the document. Do not infer, calculate, normalize, or invent any value. If a field is not explicitly stated, set value, evidence, and page to null. Evidence must be a short verbatim quote from the document that directly supports the returned value. page must be the 1-indexed page number containing the evidence. Preserve spelling, units, currency symbols, and numeric formatting as they appear in the document. If multiple values could appear to be totals, return only the one explicitly labelled as invoice total, grand total, final amount, declared value, or total. If a field is ambiguous, return null rather than choosing one candidate.

What's Next
